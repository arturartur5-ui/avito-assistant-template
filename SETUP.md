# Как запустить: по шагам

Два пути до первого ответа помощника. Шаги 1–6 ведут до работающего
тренировочного бота — это и есть «запустилось». Всё остальное (переписки, база
знаний, выход на площадку) идёт после и описано во второй половине.

**Сколько это займёт.** Шаги 1–6 — вечер работы, если ключи уже есть. Если
ключей нет: тариф Авито подключается день-три, шлюз к модели — отдельная
задача на пару часов. Обещать «два часа до клиентов» было бы неправдой.

**Что нужно на машине:** Python 3.10 или новее, git, терминал. macOS или
Linux; на Windows — через WSL. Библиотек ставить не нужно, проект работает на
стандартной библиотеке.

```bash
python3 --version    # должно быть 3.10 или больше
git --version
```

# Часть I. До работающего бота

## Шаг 1. Своя копия проекта

**Через GitHub (проще).** Кнопка **Use this template** на странице
репозитория создаёт вашу копию с чистой историей. Потом:

```bash
git clone <адрес вашей копии> ~/<клиент>-assistant
cd ~/<клиент>-assistant
```

**Клоном напрямую.** История шаблона вам не нужна, только файлы:

```bash
git clone <этот-репозиторий> ~/<клиент>-assistant
cd ~/<клиент>-assistant
rm -rf .git && git init
```

`rm -rf .git` удаляет служебную папку git внутри этой копии — файлы проекта
остаются. Набирайте ровно так и находясь в папке проекта.

Проверьте, что `.gitignore` на месте: `corpus/`, `knowledge/` и `.env` не
должны попадать в git никогда.

## Шаг 2. Создать рабочие файлы

Одна команда создаёт всё, чего не хватает, и **ничего не перезаписывает**:

```bash
python3 scripts/init.py
```

Она спросит имя специалиста и род, придумает пароль для тренировочного бота и
создаст пять файлов из образцов:

| Файл | Что в нём |
|---|---|
| `.env` | ключи и настройки, права 600 |
| `.personal-terms` | имена и метки для проверки перед коммитом |
| `prompt/SOUL.md` | системный промпт специалиста |
| `knowledge/usloviya.md` | условия и цены — единственный источник цифр |
| `TZ.md` | техзадание: точность, тональность, стоп-темы |

Запустите её ещё раз в любой момент — уже заполненное останется как есть.

**Дальше эти файлы только редактируются, а не создаются заново.** Команды
`cp .env.example .env` в инструкции нет специально: она стёрла бы то, что вы
только что вписали.

## Шаг 3. Заполнить содержание

Быстрее всего — разговором. Откройте папку в
[Claude Code](https://claude.com/claude-code) или в
[Codex](https://openai.com/codex/) и скажите:

> Проведи интервью по START-HERE.md

Полчаса вопросов о вашей работе — и `config/niche.py`, `prompt/SOUL.md`,
`knowledge/usloviya.md` заполнены вашими формулировками. Следом:

> Проведи интервью-ТЗ по START-HERE.md

Второе интервью заполняет `TZ.md`: как помощник звучит, где ему нельзя
ошибаться, о чём он молчит и по каким цифрам вы примете работу. Этот файл
подписывает специалист — по нему потом видно, помощник ошибся или просто
ответил не так, как вы себе представляли.

**Без агента** те же файлы заполняются руками: образец настройки —
`config/examples/niche-remont.py`, в самих файлах у каждого раздела есть
пример прямо в комментарии. Дольше, но ничего волшебного там нет.

Проверить настройку ниши:

```bash
python3 scripts/check-niche.py
```

## Шаг 4. Ключи и модель

Откройте `.env` **в текстовом редакторе** и заполните. Не через терминал:
bash режет escape-последовательности из буфера обмена.

**Модель.** Помощник ходит к любому OpenAI-совместимому адресу:

```
LLM_BASE_URL=https://адрес-провайдера/v1
LLM_API_KEY=ключ
LLM_MODEL=имя-модели
```

Без `https` разрешён только локальный адрес (`127.0.0.1`) — это конец
ssh-туннеля, если модель стоит за границей, а сервер с данными в России.
Поднять туннель:

```bash
ssh -N -L 8000:127.0.0.1:8000 пользователь@ваш-шлюз
```

**Где брать шлюз, если модель недоступна из России напрямую.** Нужен самый
простой зарубежный VPS — на нём поднимается OpenAI-совместимый шлюз, а
российский сервер ходит к нему через туннель. Из проверенного:
[Hostinger](https://www.hostinger.com/vps-hosting) — берётся минимальный
тариф, оплата картой, ключи моделей остаются на этой машине и в Россию не
попадают. Подойдёт любой другой зарубежный VPS, разницы для проекта нет.

**Российский сервер** (там живут переписки и база) выбирайте сами:
[Timeweb](https://timeweb.cloud/), [Beget](https://beget.com/ru/cloud) — оба
подходят. Требование одно и оно из закона: данные клиентов лежат в России.

Шлюз, туннель и оплату модели шаблон не поднимает — это ваша инфраструктура.

**Тренировочный бот.** У @BotFather в Telegram командой `/newbot` заводится
отдельный бот (не рабочий!), он выдаёт токен вида `1234567890:AA...`:

```
TELEGRAM_BOT_TOKEN=токен
```

Пароль `EXAM_PASSWORD` уже сгенерирован шагом 2.

**Ключи Авито** (для переписок, понадобятся в части II): кабинет клиента →
«Для профессионалов» → «API». Нужна бизнес-подписка — **от 3 000 ₽ в месяц**
за самый дешёвый тариф, этого достаточно, чтобы Авито открыл доступ к API.
Значения копировать **только кнопкой**: в шрифте Авито `1`, `l` и `I`
неразличимы.

## Шаг 5. Проверить готовность

```bash
python3 scripts/check-env.py
```

Показывает одним списком: версия Python, переменные по этапам, промпт, файл
условий и его срок, настройка ниши, права на файлы с ключами, установлены ли
проверки перед коммитом. Крестики против этапа, до которого вы ещё не дошли, —
это норма.

Поставьте проверки перед коммитом (посмотрите сначала, что внутри):

```bash
sh scripts/install-hooks.sh
```

Дальше `git commit` не пройдёт, если в изменениях окажется имя из
`.personal-terms`, правдоподобный телефон, почта, паспорт или карта.

Это не перестраховка. При сборке шаблона данные клиента просачивались в код
трижды — через комментарии, примеры и названия исключаемых чатов.

**Правило, из которого всё следует:** если в коде появилось что-то, что у
следующего клиента будет другим, — это не код, это настройка.

Убедиться, что каркас цел:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests
```

Строки «ВНИМАНИЕ» и «HTTP 500» между точками — так задумано, тесты проверяют
и поведение при сбоях.

## Шаг 6. Запустить тренировочного бота

```bash
python3 src/tg_exam_bot.py
```

Специалист пишет боту `/start ПАРОЛЬ` (пароль передайте лично, не в переписке
с клиентами). Бот отвечает как помощник, под каждым ответом три кнопки:
**верно / неточно / неверно**. На «неточно» и «неверно» специалист пишет, как
правильно, — правка сохраняется.

Работает опросом: ни сервера, ни домена, ни вебхуков не нужно, можно гонять с
ноутбука. Клиентов бот не видит.

**Чего ждать в первые дни — чтобы не решить, что сломалось.** Помощник будет
много молчать: пока в `knowledge/usloviya.md` нет цифр, а в корпусе нет
переписок, ему нечем отвечать по делу, и он выбирает молчание вместо выдумки.
Разговорчивее он становится от двух вещей: заполненных условий и правок на
экзамене.

Тревожиться стоит не когда он молчит, а когда называет цифру, которой нет в
`knowledge/usloviya.md`, или обещает результат. Такое — сразу «неверно» и
правка в скобках: `[цифру не называть]`.

**Посмотреть, как всё устроено, вообще без ключей:**

```bash
python3 scripts/demo.py
```

Поднимает подставной шлюз в том же процессе и прогоняет несколько учебных
сообщений: видно, что уходит модели, что уходит клиенту и почему помощник
замолчал.

# Часть II. Дальше: голос, площадка, автономия

## Шаг 7. Собрать корпус переписок

Голос помощника берётся из переписок специалиста. Их не обязательно иметь
сразу — см. «Если переписок мало» в README.

**Авито:**

```bash
python3 src/export_corpus.py --limit 40   # сначала проба
python3 src/export_corpus.py              # потом целиком
```

Выгрузка обезличивает в памяти — сырые данные на диск не пишутся. Глубже 1000
чатов постранично не выгрузить, это ограничение площадки.

**Telegram:** экспорт из Telegram Desktop («Настройки» → «Продвинутые
настройки» → «Экспорт данных Telegram»), формат **JSON**, медиа снять.

```bash
python3 src/import_telegram.py ~/tg-export/result.json --owner "Имя как в экспорте"
python3 src/import_channel.py ~/tg-export/kanal.json --owner "Имя как в экспорте"
```

Берутся только рабочие чаты: те, где слова ниши встречаются не реже
`TOPIC_MIN_HITS` раз. Слова — в `.env`, строка `TOPIC_KEYWORDS` (в образце
стоят слова для ипотеки, замените на свои). «Избранное», группы и чаты из
`EXCLUDE_CHATS` не берутся никогда.

`--owner` — кто из участников специалист: его реплики попадут в корпус как
ответы. Без флага владельцем считается тот, кто написал больше всех; скрипт
печатает, кого выбрал, — проверьте.

## Шаг 8. Проверить, что ничего не утекло

**Обязательный шаг, и он должен показать ноль находок:**

```bash
python3 scripts/check-corpus.py
```

Прогоняет корпус и базу знаний через ту же проверку, что стоит на двери
наружу: телефоны во всех написаниях, почты, документы, карты, ссылки, ники,
имена, координаты. Печатает, что и где нашлось, — без самих значений.

Нашлось — правило дописывается в `src/anonymize.py` вместе с тестом на эту
форму, и корпус собирается заново. Задним числом правка правил уже
выгруженные файлы не чинит.

**Сырые выгрузки после этого удалите.** Смысл в том, чтобы на машине не
возникало базы персональных данных.

## Шаг 9. Собрать базу знаний

```
knowledge/
├── usloviya.md      цифры и условия (заполнено на шаге 3)
├── articles/        готовые материалы клиента, только .md
└── ...              заметки, посты каналов
```

Черновики и промежуточные версии не брать — в них противоречия. Двоичные
файлы не индексируются: правило в `src/indexing_rules.py`, обойти нельзя.

Индекс собирается сам при запуске. Посмотреть, что в него попало и сколько
окон диалогов выброшено:

```bash
python3 src/chunking.py
```

## Шаг 10. Промпт на шлюзе (если он там живёт)

Движок отправляет `prompt/SOUL.md` сам, отдельным системным сообщением. Если
у вас промпт закреплён на шлюзе в профиле модели, выложить его туда:

```bash
./scripts/sync-prompt.sh push     # выложить
./scripts/sync-prompt.sh check    # сверить
```

Адрес шлюза, путь к файлу и команду перезапуска скрипт берёт из `.env` —
строки `GATEWAY_*` (в `.env.example` закомментированы).

## Шаг 11. Выход на площадку

Порядок в `docs/zapusk.md`, нарушать его нельзя: экзамен → черновики →
автономия.

**Этап 2, черновики.** Помощник готовит ответ, отправляет специалист:

```bash
python3 src/draft_loop.py --dry-run   # посмотреть связку
python3 src/draft_loop.py             # рабочий режим
```

Нужен `DRAFT_OWNER_CHAT` в `.env` — id чата специалиста с ботом. Узнать: в
тренировочном боте команда `/id`, или посмотреть в его выводе при входе.

Черновики приходят в Telegram с кнопками; клиенту не уходит ничего, пока
кнопку не нажали. Это эталон под правку: у каждого свой способ подтверждать
ответы, подробности и оговорки — в `docs/zapusk.md`.

**Этап 3, автономия** — не отдельный код, а решение расширять список тем, где
помощник отвечает сам.

## Шаг 12. Ежедневный разбор правок

Каждая правка специалиста в тренировочном боте — это будущее правило, а не
пожелание модели. Разбирайте их каждый день, пока идёт экзамен:

- замечание в квадратных скобках («[подрядчика не называть]») → правило в
  `config/niche.py`;
- рекомендуемый ответ → пример в базу знаний;
- повторяющаяся ошибка → детерминированная правка, чтобы она не зависела от
  модели.

Правки, внедрённые только в промпт, отваливаются при смене модели. Всё, что
критично — контакты, цены, обещания, деликатные темы — должно держаться
фильтром.

Метрики фильтра, чтобы он не задерживал лишнего:

```bash
python3 scripts/guard-metrics.py .
```

## Если что-то не получилось

| Что видите | Что это значит |
|---|---|
| `LLM_BASE_URL не задан` | не заполнен `.env` — `python3 scripts/check-env.py` покажет всё сразу |
| `Нужен TELEGRAM_BOT_TOKEN` | бот не заведён или токен не вписан (шаг 4) |
| `EXAM_PASSWORD остался образцовым` | пароль из образца лежит в открытом репозитории — поставьте свой |
| `Не заданы ключи` у Авито | ключи не вписаны; если вписаны — проверьте тариф и что копировали кнопкой |
| `цифры заморожены` | в `knowledge/usloviya.md` нет строки «Годен до» или срок прошёл |
| `запрос не отправлен: на выходе остались персональные данные` | шлюз ни при чём: сработала своя проверка — в тексте что-то похожее на телефон или документ. Что именно — в `logs/leak.log`, там классы находок без значений |
| `нет prompt/SOUL.md` | промпт не создан: `python3 scripts/init.py` |
| `TOPIC_KEYWORDS в .env пуст` | не заданы слова ниши — импорт не отличит рабочие чаты от личных |
| помощник всё время молчит | нормально в первые дни; ненормально, если он называет цифры |

## Чего нельзя менять

Правила в `CLAUDE.md` и `docs/` — не декоративные, за каждым стоит конкретный
риск: штраф по 152-ФЗ или ограничение чатов на площадке. Прежде чем ослаблять,
прочитайте `docs/pdn-i-zakony.md` и `docs/pravila-avito.md`.

## Кто отвечает за данные

Оператор персональных данных — **тот специалист, чей это аккаунт**, а не
подрядчик, который настраивает помощника. Переписки, клиенты и ответственность
по 152-ФЗ принадлежат его юридическому лицу или ИП.

Из этого следует:
- уведомление в РКН, политика обработки и согласия — на стороне специалиста;
- подрядчику нужно **поручение на обработку** по ст. 6 ч. 3 152-ФЗ, письменно;
- корпус и база знаний — собственность специалиста, в репозиторий подрядчика
  они не попадают никогда.

Если вы настраиваете помощника **сами себе** — поручение не нужно, вы и есть
оператор. Локализация данных в России и уведомление в РКН остаются.
