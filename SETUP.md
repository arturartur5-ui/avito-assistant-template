# Как запустить: по шагам

Два пути до первого ответа помощника. Шаги 1–6 ведут до работающего
тренировочного бота — это и есть «запустилось». Всё остальное (переписки, база
знаний, выход на площадку) идёт после и описано во второй половине.

**Сколько это займёт.** Шаги 1–6 — вечер работы, если ключи уже есть. Если
ключей нет: тариф Авито подключается день-три, шлюз к модели — отдельная
задача на пару часов. Обещать «два часа до клиентов» было бы неправдой.

**Что нужно на машине:** Python 3.10 или новее, git, терминал. macOS или
Linux; на Windows — через WSL. Библиотек ставить не нужно, проект работает на
стандартной библиотеке.

```bash
python3 --version    # должно быть 3.10 или больше
git --version
```

# Часть I. До работающего бота

## Шаг 1. Своя копия проекта

**Через GitHub (проще).** Кнопка **Use this template** на странице
репозитория создаёт вашу копию с чистой историей. Потом:

```bash
git clone <адрес вашей копии> ~/<клиент>-assistant
cd ~/<клиент>-assistant
```

**Клоном напрямую.** История шаблона вам не нужна, только файлы:

```bash
git clone <этот-репозиторий> ~/<клиент>-assistant
cd ~/<клиент>-assistant
rm -rf .git && git init
```

`rm -rf .git` удаляет служебную папку git внутри этой копии — файлы проекта
остаются. Набирайте ровно так и находясь в папке проекта.

Проверьте, что `.gitignore` на месте: `corpus/`, `knowledge/` и `.env` не
должны попадать в git никогда.

Если git ещё не знает, кто вы, назовитесь один раз — иначе первый коммит
подпишется именем компьютера и настоящей почтой:

```bash
git config --global user.name "Имя"
git config --global user.email "<адрес-заглушка из GitHub: Settings → Emails → Keep my email private>"
```

## Шаг 2. Создать рабочие файлы

Одна команда создаёт всё, чего не хватает, и **ничего не перезаписывает**:

```bash
python3 scripts/init.py
```

Она спросит имя специалиста и род, придумает пароль для тренировочного бота и
создаст пять файлов из образцов:

| Файл | Что в нём |
|---|---|
| `.env` | ключи и настройки, права 600 |
| `.personal-terms` | имена и метки для проверки перед коммитом |
| `prompt/SOUL.md` | системный промпт специалиста |
| `knowledge/usloviya.md` | условия и цены — единственный источник цифр |
| `TZ.md` | техзадание: точность, тональность, стоп-темы |

Запустите её ещё раз в любой момент — уже заполненное останется как есть.

**Дальше эти файлы только редактируются, а не создаются заново.** Команды
`cp .env.example .env` в инструкции нет специально: она стёрла бы то, что вы
только что вписали.

## Шаг 3. Заполнить содержание

Быстрее всего — разговором. Откройте папку в
[Claude Code](https://claude.com/claude-code) или в
[Codex](https://openai.com/codex/) и скажите:

> Проведи интервью по START-HERE.md

Полчаса вопросов о вашей работе — и `config/niche.py`, `prompt/SOUL.md`,
`knowledge/usloviya.md` заполнены вашими формулировками. Следом:

> Проведи интервью-ТЗ по START-HERE.md

Второе интервью заполняет `TZ.md`: как помощник звучит, где ему нельзя
ошибаться, о чём он молчит и по каким цифрам вы примете работу. Этот файл
подписывает специалист — по нему потом видно, помощник ошибся или просто
ответил не так, как вы себе представляли.

**Без агента** те же файлы заполняются руками: образец настройки —
`config/examples/niche-remont.py`, в самих файлах у каждого раздела есть
пример прямо в комментарии. Дольше, но ничего волшебного там нет.

Проверить настройку ниши:

```bash
python3 scripts/check-niche.py
```

## Шаг 4. Ключи и модель

Откройте `.env` **в текстовом редакторе** и заполните. Не через терминал:
bash режет escape-последовательности из буфера обмена.

**Модель.** Помощник ходит к любому OpenAI-совместимому адресу:

```
LLM_BASE_URL=https://адрес-провайдера/v1
LLM_API_KEY=ключ
LLM_MODEL=имя-модели
```

Без `https` разрешён только локальный адрес (`127.0.0.1`) — это конец
ssh-туннеля, если модель стоит за границей, а сервер с данными в России.
Поднять туннель:

```bash
ssh -N -L 8000:127.0.0.1:8000 пользователь@ваш-шлюз
```

**Туннель должен подниматься сам.** Команда выше — чтобы один раз проверить
руками, что связь есть. Для постоянной работы она не годится: моргнул
интернет — туннель упал, помощник замолчал и молчит, пока кто-нибудь не
заметит. На российском сервере туннель заводится службой, которая сама его
поднимает обратно:

```bash
apt install autossh
```

Файл `/etc/systemd/system/llm-tunnel.service`:

```ini
[Unit]
Description=Туннель к шлюзу: доступ к модели без открытых портов
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
Restart=always
RestartSec=10
Environment=AUTOSSH_GATETIME=0
ExecStart=/usr/bin/autossh -M 0 -N \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -o ExitOnForwardFailure=yes -o IdentitiesOnly=yes \
  -i /root/.ssh/имя-вашего-ключа-до-шлюза \
  -L 127.0.0.1:8000:127.0.0.1:8000 \
  пользователь@адрес-вашего-шлюза

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now llm-tunnel
systemctl status llm-tunnel       # должно быть active (running)
```

Три строчки в этом файле делают всю работу, и выкидывать их не стоит.
`Restart=always` поднимает туннель после обрыва. `ServerAliveInterval`
заставляет каждые полминуты проверять, жив ли тот конец, — иначе повисшее
соединение выглядит рабочим, а запросы просто уходят в никуда.
`ExitOnForwardFailure` не даёт службе притвориться живой, когда порт занять
не удалось.

**Где брать шлюз, если модель недоступна из России напрямую.** Нужен самый
простой зарубежный VPS — на нём поднимается OpenAI-совместимый шлюз, а
российский сервер ходит к нему через туннель. Из проверенного:
[Hostinger](https://www.hostinger.com/vps-hosting) — берётся минимальный
тариф, оплата картой, ключи моделей остаются на этой машине и в Россию не
попадают. Подойдёт любой другой зарубежный VPS, разницы для проекта нет.

**Российский сервер** (там живут переписки и база) выбирайте сами:
[Timeweb](https://timeweb.cloud/), [Beget](https://beget.com/ru/cloud) — оба
подходят. Требование одно и оно из закона: данные клиентов лежат в России.

**Какую программу ставить на шлюз.** Задача у него одна: принять запрос от
российского сервера и передать провайдеру, подставив ключ. Ключ модели лежит
только здесь и в Россию не уезжает.

Сначала проверьте, нужен ли шлюз вообще. Провайдер открывается из России
напрямую — впишите его адрес в `LLM_BASE_URL` и пропустите этот раздел вместе
с VPS и туннелем. Лишний посредник никому не нужен.

**LiteLLM** — когда у провайдера обычный ключ (`sk-...`). Понимает почти всех
и отвечает по OpenAI-совместимому протоколу:

```bash
pip install 'litellm[proxy]'
litellm --config config.yaml --host 127.0.0.1 --port 8000
```

`config.yaml` кладётся рядом:

```yaml
model_list:
  - model_name: assistant
    litellm_params:
      model: openai/gpt-4o             # ваш провайдер и модель
      api_key: os.environ/PROVIDER_KEY # ключ берётся из окружения, не из файла
general_settings:
  master_key: sk-свой-длинный-пароль   # им шлюз пускает к себе, обязательно с sk-
```

Тогда в `.env` российского сервера: `LLM_MODEL=assistant`,
`LLM_API_KEY=sk-свой-длинный-пароль`, `LLM_BASE_URL` — конец туннеля.

**Hermes** — когда модель даётся по входу в аккаунт, а не по ключу (Nous
Portal, xAI Grok). Вписывать в LiteLLM тут просто нечего:

```bash
pip install hermes-agent
hermes proxy start --provider nous --port 8000
```

Список провайдеров — `hermes proxy providers`. Hermes вообще-то большая
агентная платформа (MIT, [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)),
и из неё здесь нужна ровно одна команда — остальное можно не трогать.

**Шлюз слушает только сам себя.** `--host 127.0.0.1` в командах выше не для
красоты: LiteLLM по умолчанию встаёт на `0.0.0.0`, а это «открыт всему
интернету» — кто найдёт адрес, тот и тратит ваш ключ, пока не кончатся деньги.
Наружу шлюз выходит исключительно через ssh-туннель. После запуска проверьте:

```bash
ss -lntp | grep 8000      # адрес должен быть 127.0.0.1, а не 0.0.0.0
```

Шлюз, туннель и оплату модели шаблон не поднимает — это ваша инфраструктура.

**Тренировочный бот.** У @BotFather в Telegram командой `/newbot` заводится
отдельный бот (не рабочий!), он выдаёт токен вида `1234567890:AA...`:

```
TELEGRAM_BOT_TOKEN=токен
```

Пароль `EXAM_PASSWORD` уже сгенерирован шагом 2.

**Ключи Авито** (для переписок, понадобятся в части II): кабинет клиента →
«Для профессионалов» → «API». Нужна бизнес-подписка — **от 3 000 ₽ в месяц**
за самый дешёвый тариф, этого достаточно, чтобы Авито открыл доступ к API.
Значения копировать **только кнопкой**: в шрифте Авито `1`, `l` и `I`
неразличимы.

## Шаг 5. Проверить готовность

```bash
python3 scripts/check-env.py
```

Показывает одним списком: версия Python, переменные по этапам, промпт, файл
условий и его срок, настройка ниши, права на файлы с ключами, установлены ли
проверки перед коммитом. Крестики против этапа, до которого вы ещё не дошли, —
это норма.

Поставьте проверки перед коммитом (посмотрите сначала, что внутри):

```bash
sh scripts/install-hooks.sh
```

Дальше `git commit` не пройдёт, если в изменениях окажется имя из
`.personal-terms`, правдоподобный телефон, почта, паспорт или карта.

Это не перестраховка. При сборке шаблона данные клиента просачивались в код
трижды — через комментарии, примеры и названия исключаемых чатов.

**Правило, из которого всё следует:** если в коде появилось что-то, что у
следующего клиента будет другим, — это не код, это настройка.

Убедиться, что каркас цел:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests
```

Строки «ВНИМАНИЕ» и «HTTP 500» между точками — так задумано, тесты проверяют
и поведение при сбоях.

## Шаг 6. Запустить тренировочного бота

```bash
python3 src/tg_exam_bot.py
```

Специалист пишет боту `/start ПАРОЛЬ` (пароль передайте лично, не в переписке
с клиентами). Бот отвечает как помощник, под каждым ответом три кнопки:
**верно / неточно / неверно**. На «неточно» и «неверно» специалист пишет, как
правильно, — правка сохраняется.

Работает опросом: ни сервера, ни домена, ни вебхуков не нужно, можно гонять с
ноутбука. Клиентов бот не видит.

**Чего ждать в первые дни — чтобы не решить, что сломалось.** Помощник будет
часто передавать разговор: пока в `knowledge/usloviya.md` нет цифр, а в
корпусе нет переписок, ему нечем отвечать по делу, и он выбирает передачу
вместо выдумки. Разговорчивее он становится от двух вещей: заполненных условий
и правок на экзамене.

Нормальная передача всегда с причиной, которую видно в боте: «вход: …»,
«выход: …», «цифры заморожены». А вот **«запрос не отправлен: на выходе
остались персональные данные»** на обычном вопросе — это не норма, а дефект
обезличивания: покажите строку из `logs/leak.log` разработчику или агенту,
правило дописывается в `src/anonymize.py`.

Тревожиться стоит и когда он называет цифру, которой нет в
`knowledge/usloviya.md`, или обещает результат. Такое — сразу «неверно» и
правка в скобках: `[цифру не называть]`.

**Посмотреть, как всё устроено, вообще без ключей:**

```bash
python3 scripts/demo.py
```

Поднимает подставной шлюз в том же процессе и прогоняет несколько учебных
сообщений: видно, что уходит модели, что уходит клиенту и почему помощник
замолчал.

# Часть II. Дальше: голос, площадка, автономия

## Шаг 7. Собрать корпус переписок

Голос помощника берётся из переписок специалиста. Их не обязательно иметь
сразу — см. «Если переписок мало» в README.

### 7.1. Переписки Авито — через API

Нужны ключи из шага 4. Сначала убедитесь, что площадка вас пускает:

```bash
python3 src/avito_business.py token
```

Ответ «OK. Токен получен, отпечаток sha256:…» — значит можно выгружать.
Ошибка — вернитесь к шагу 4: чаще всего дело в тарифе или в том, что ключи
набирали руками, а не копировали кнопкой.

```bash
python3 src/export_corpus.py --limit 40   # сначала проба на 40 чатах
python3 src/export_corpus.py              # потом целиком
```

Первую команду стоит выполнить обязательно: она за пару минут покажет, что
получается, и не сожжёт час на полной выгрузке, если что-то настроено не так.

**Что появится** в `corpus/` (права 700, только для вас):

| Файл | Что внутри |
|---|---|
| `dialogs.jsonl` | диалоги целиком, реплики размечены `client` / `specialist` |
| `qa_pairs.jsonl` | пары «вопрос клиента → ответ специалиста» |
| `stats.json` | сводка: сколько диалогов, реплик, частые темы |
| `.checkpoint` | отметки о выгруженных чатах, чтобы продолжить после обрыва |

Сырые переписки на диск не попадают вообще: текст обезличивается в памяти, и
на машину ложится только очищенный результат.

**Сколько ждать.** Тысяча чатов — примерно час: площадка отдаёт их
постранично и ограничивает частоту запросов. Выгрузка печатает прогресс
каждые 25 чатов. Оборвалась или закрыли ноутбук — продолжите с того же места:

```bash
python3 src/export_corpus.py --resume
```

**Ограничение площадки:** глубже 1000 чатов постранично не выгрузить. Если
переписок больше, возьмётся последняя тысяча — этого достаточно.

По умолчанию берутся чаты по вашим объявлениям. Если специалист в части
переписок сам был покупателем и эти диалоги тоже нужны — добавьте
`--all-chats`.

### 7.2. Переписки Telegram — через экспорт в JSON

Экспорт делается **только в Telegram Desktop** на компьютере: в мобильном
приложении такой возможности нет.

1. Откройте Telegram Desktop → **Настройки** → **Продвинутые настройки** →
   **Экспорт данных Telegram**.
2. Отметьте **«Личные чаты»**. Остальное — группы, каналы, боты, звонки —
   снимите.
3. Снимите **все галочки с медиа**: фото, видео, голосовые, файлы, стикеры.
   Они не нужны, а с ними экспорт весит десятки гигабайт и идёт сутками.
4. Формат — **JSON** (не HTML: HTML этот импорт не читает).
5. Нажмите «Экспортировать». Telegram может попросить подождать до 24 часов —
   это его защита, ничего сделать нельзя, придёт уведомление.

Готовый файл — `result.json`, обычно в `~/Downloads/Telegram Desktop/DataExport_ГГГГ-ММ-ДД/`.

```bash
python3 src/import_telegram.py ~/Downloads/"Telegram Desktop"/DataExport_2026-09-22/result.json \
    --owner "Имя Фамилия как в Telegram"
```

`--owner` — кто из собеседников специалист: его реплики лягут в корпус как
ответы, остальные как вопросы. Без флага владельцем считается тот, кто
написал больше всех; скрипт печатает, кого выбрал, — проверьте эту строку,
она важнее остальных.

**Что берётся.** Только рабочие чаты: те, где слова вашей ниши встречаются не
реже `TOPIC_MIN_HITS` раз. Слова — в `.env`, строка `TOPIC_KEYWORDS`; в
образце стоят слова для ремонта, замените на свои, иначе не найдётся ни
одного чата. «Избранное», группы и чаты из `EXCLUDE_CHATS` не берутся
никогда. Вложения не скачиваются: в корпусе от них остаётся только тип.

### 7.3. Свой канал в Telegram — отдельным экспортом

Посты канала — это готовые статьи специалиста, они идут не в корпус
диалогов, а в базу знаний. Канал экспортируется **отдельно** от личных
чатов: откройте канал в Telegram Desktop → меню (⋮) → **Экспорт истории
чата** → JSON, медиа снять.

```bash
python3 src/import_channel.py ~/Downloads/"Telegram Desktop"/ChatExport_2026-09-22/result.json \
    --owner "Имя Фамилия"
```

Результат ляжет в `knowledge/`. Короткие посты (меньше 40 знаков) не берутся —
это анонсы и реакции, а не материал; порог меняется флагом `--min-len`.

## Шаг 8. Проверить, что ничего не утекло

**Обязательный шаг, и он должен показать ноль находок:**

```bash
python3 scripts/check-corpus.py
```

Прогоняет корпус и базу знаний через ту же проверку, что стоит на двери
наружу: телефоны во всех написаниях, почты, документы, карты, ссылки, ники,
имена, координаты. Печатает, что и где нашлось, — без самих значений.

Нашлось — правило дописывается в `src/anonymize.py` вместе с тестом на эту
форму, и корпус собирается заново. Задним числом правка правил уже
выгруженные файлы не чинит.

**Сырые выгрузки после этого удалите.** Смысл в том, чтобы на машине не
возникало базы персональных данных.

## Шаг 9. Собрать базу знаний

Переписки дают голос, база знаний — содержание. У специалиста обычно уже всё
это есть, просто лежит по разным папкам. Попросите принести:

| Что принести | Куда положить | Зачем |
|---|---|---|
| **Прайс, расценки, тарифы** | цифры — в `knowledge/usloviya.md`, сам прайс — в `knowledge/` | чтобы помощник называл ваши цены, а не выдуманные |
| Коммерческое предложение, презентация услуг | `knowledge/articles/` | как вы объясняете ценность |
| Ответы на частые вопросы, памятка клиенту | `knowledge/articles/` | половина переписки — это они |
| Описание услуг, состав работ, этапы | `knowledge/articles/` | помощник объяснит, что входит в работу |
| Договор, регламент, гарантийные условия | `knowledge/articles/` | ответы про сроки, гарантию, порядок оплаты |
| Статьи, посты, разборы случаев | `knowledge/articles/` | экспертиза вашими словами |
| Внутреннее: поставщики, закупочные цены, стратегии | `knowledge/internal/` | помощник это знает, но клиенту не скажет |

```
knowledge/
├── usloviya.md      цифры и условия — единственный источник цифр
├── articles/        материалы: КП, FAQ, описания, договор, статьи
├── internal/        внутренняя кухня, в индекс не попадает никогда
└── ...              отдельные заметки
```

**Форматы:** `.md`, `.txt`, `.csv`. Прайс, выгруженный из таблицы в CSV, и
регламент из блокнота читаются наравне со статьями.

**PDF, Word, Excel, фото и сканы не индексируются** — их нельзя проверить на
личные данные текстовым аудитом, а в договоре или счёте почти всегда есть
чьё-то имя. Нужный материал переведите в текст сами: скопируйте содержимое в
`.txt` или `.md` и **по дороге уберите имена, телефоны и реквизиты** — ваши и
чужие.

**Цифры — особый случай.** Всё, что помощник произносит как цену, ставку или
срок, он берёт **только** из `knowledge/usloviya.md`. Прайс, который вы
положите в `articles/`, поможет ему понять, о чём речь, но называть числа
оттуда он не станет: для него они архивные. Поэтому актуальные цены
переносите в `usloviya.md`, в раздел «Стоимость услуг», и проставляйте срок
годности.

Черновики и промежуточные версии не брать — в них противоречия.

Индекс собирается сам при запуске. Посмотреть, что в него попало и сколько
окон диалогов выброшено:

```bash
python3 src/chunking.py
```

## Когда помощник останавливается и зовёт вас

Это не сбой, а главный предохранитель: там, где ошибка дорога, отвечает
человек. Помощник пишет клиенту короткую фразу («вернусь к вам чуть позже с
ответом») и передаёт разговор — в тренировочном боте и в черновиках видно
причину.

**По сообщению клиента, ещё до обращения к модели:**

| Повод | Пример |
|---|---|
| оставил свой контакт | прислал телефон, почту, ник |
| зовёт в другой мессенджер | «давайте в вотсап», «пишите в телеграм» |
| спросил, не бот ли вы | «это робот?», «вы живой человек?» |
| раздражён или недоволен | «вы не отвечаете по делу», «хватит общих слов» |
| срочная ситуация | «горит», «сделка срывается», «отказали за час» |
| просит посчитать, пока картина не собрана | «сколько будет стоить?» до того, как выяснены нужные вещи |
| деликатная тема вашей ниши | то, что вы перечислили в `SENSITIVE_TOPICS` |
| не ваше направление | то, что вы перечислили в `NOT_OUR_WORK` |
| политика | любой поворот в эту сторону |
| просьба о незаконном | то, что вы перечислили в `ILLEGAL_RULES` |

**По ответу модели, перед отправкой клиенту:**

| Повод | Что это значит |
|---|---|
| контакты или увод с площадки | модель написала телефон, ссылку, ник — прямое нарушение правил площадки |
| обещание результата | «одобрят», «гарантирую», «точно получится» |
| раскрытие помощника | признание «я бот» или упоминание передачи словами |
| внутренняя кухня | назвала поставщика, партнёра, подрядчика из вашего списка |
| цена не вовремя | заговорила о деньгах раньше, чем собрана картина |
| расчёт | взялась считать смету или платёж |
| оплата от партнёров | как и сколько вам платят |
| неуверенность | «наверное», «кажется» — сомнение клиенту не показываем |
| остаток обезличивания | в ответе всплыл `[ИМЯ]` или другая метка |
| цифры заморожены | в `knowledge/usloviya.md` истёк или не проставлен срок годности |

**Отдельно:** если перед отправкой к модели в тексте осталось похожее на
личные данные, запрос не уходит вообще — ни к какой модели. Разговор
передаётся вам, а причина пишется в `logs/leak.log`. На обычном вопросе это
означает дефект обезличивания, а не норму (см. шаг 6).

Все поводы, кроме технических, вы задаёте сами в `config/niche.py` — интервью
заполняет их вашими словами.

## Шаг 10. Промпт на шлюзе (если он там живёт)

Движок отправляет `prompt/SOUL.md` сам, отдельным системным сообщением. Если
у вас промпт закреплён на шлюзе в профиле модели, выложить его туда:

```bash
./scripts/sync-prompt.sh push     # выложить
./scripts/sync-prompt.sh check    # сверить
```

Адрес шлюза, путь к файлу и команду перезапуска скрипт берёт из `.env` —
строки `GATEWAY_*` (в `.env.example` закомментированы).

## Шаг 11. Выход на площадку

Порядок в `docs/zapusk.md`, нарушать его нельзя: экзамен → черновики →
автономия.

**Этап 2, черновики.** Помощник готовит ответ, отправляет специалист:

```bash
python3 src/draft_loop.py --dry-run   # посмотреть связку
python3 src/draft_loop.py             # рабочий режим
```

Нужен `DRAFT_OWNER_CHAT` в `.env` — id чата специалиста с ботом. Узнать: в
тренировочном боте команда `/id`, или посмотреть в его выводе при входе.

Черновики приходят в Telegram с кнопками; клиенту не уходит ничего, пока
кнопку не нажали. Это эталон под правку: у каждого свой способ подтверждать
ответы, подробности и оговорки — в `docs/zapusk.md`.

**Этап 3, автономия** — не отдельный код, а решение расширять список тем, где
помощник отвечает сам.

## Шаг 12. Ежедневный разбор правок

Каждая правка специалиста в тренировочном боте — это будущее правило, а не
пожелание модели. Разбирайте их каждый день, пока идёт экзамен:

- замечание в квадратных скобках («[подрядчика не называть]») → правило в
  `config/niche.py`;
- рекомендуемый ответ → пример в базу знаний;
- повторяющаяся ошибка → детерминированная правка, чтобы она не зависела от
  модели.

Правки, внедрённые только в промпт, отваливаются при смене модели. Всё, что
критично — контакты, цены, обещания, деликатные темы — должно держаться
фильтром.

Метрики фильтра, чтобы он не задерживал лишнего:

```bash
python3 scripts/guard-metrics.py .
```

## Если что-то не получилось

| Что видите | Что это значит |
|---|---|
| `сбой шлюза: … Connection refused` | по адресу `LLM_BASE_URL` никто не отвечает: туннель не поднят или адрес из образца. `python3 scripts/check-env.py` покажет, что оставлено из образца |
| `LLM_BASE_URL не задан` | не заполнен `.env` — `python3 scripts/check-env.py` покажет всё сразу |
| `Нужен TELEGRAM_BOT_TOKEN` | бот не заведён или токен не вписан (шаг 4) |
| `EXAM_PASSWORD остался образцовым` | пароль из образца лежит в открытом репозитории — поставьте свой |
| `Не заданы ключи` у Авито | ключи не вписаны; если вписаны — проверьте тариф и что копировали кнопкой |
| `цифры заморожены` | в `knowledge/usloviya.md` нет строки «Годен до» или срок прошёл |
| `запрос не отправлен: на выходе остались персональные данные` | шлюз ни при чём: сработала своя проверка — в тексте что-то похожее на телефон или документ. Что именно — в `logs/leak.log`, там классы находок без значений |
| `нет prompt/SOUL.md` | промпт не создан: `python3 scripts/init.py` |
| `TOPIC_KEYWORDS в .env пуст` | не заданы слова ниши — импорт не отличит рабочие чаты от личных |
| помощник всё время молчит | нормально в первые дни; ненормально, если он называет цифры |

## Чего нельзя менять

Правила в `CLAUDE.md` и `docs/` — не декоративные, за каждым стоит конкретный
риск: штраф по 152-ФЗ или ограничение чатов на площадке. Прежде чем ослаблять,
прочитайте `docs/pdn-i-zakony.md` и `docs/pravila-avito.md`.

## Кто отвечает за данные

Оператор персональных данных — **тот специалист, чей это аккаунт**, а не
подрядчик, который настраивает помощника. Переписки, клиенты и ответственность
по 152-ФЗ принадлежат его юридическому лицу или ИП.

Из этого следует:
- уведомление в РКН, политика обработки и согласия — на стороне специалиста;
- подрядчику нужно **поручение на обработку** по ст. 6 ч. 3 152-ФЗ, письменно;
- корпус и база знаний — собственность специалиста, в репозиторий подрядчика
  они не попадают никогда.

Если вы настраиваете помощника **сами себе** — поручение не нужно, вы и есть
оператор. Локализация данных в России и уведомление в РКН остаются.
