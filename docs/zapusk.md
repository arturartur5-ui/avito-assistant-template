# Как запускать: три этапа

Помощник не включается на клиентов сразу. Сначала он сдаёт экзамен, потом
работает под присмотром, и только потом получает автономию.

## Этап 1. Экзамен в Telegram

Тот же движок, другой вход. Telegram-бот, доступ только у специалиста.

Он задаёт вопросы, бот отвечает, под каждым ответом три кнопки: **верно**,
**неточно**, **неверно**. Нажал «неточно» или «неверно» — пишет, как
правильно. Каждая правка сохраняется в базу оценок (`data/exam.db`); в базу
знаний и промпт их переносят разбором — SETUP, шаг 12.

Неделя такого допроса даёт больше, чем месяц ручной настройки промпта.

**Критерий сдачи — цифры, а не ощущение:** 50 вопросов подряд без «неверно»
и покрытие всех тем. Пока не сдал — на площадку не выходит. Полный список
проверок — в вашем `TZ.md`, раздел «Критерий приёмки» (шаблон —
`TZ.template.md`, заполняется интервью из `START-HERE.md`).

На этом этапе не нужен ни сервер, ни домен, ни вебхуки: Telegram-бот работает
через опрос, его можно гонять с ноутбука.

Персональных данных клиентов здесь нет — вопросы учебные. Что бот всё же
хранит: `data/exam.db` — Telegram `chat_id` участников, их вопросы, ответы
помощника и правки, всё обезличенное. Имя из Telegram не пишется. Участник
стирает себя командой `/забыть`; сообщение с паролем бот удаляет из чата
сразу после входа. Закончили экзамен — удалите файл целиком, он больше не
нужен.

## Этап 2. Черновик на площадке

Бот видит сообщение клиента, готовит ответ, но **не отправляет**. Шлёт
специалисту: «клиент спрашивает X, я хочу ответить Y», кнопки «отправить»,
«поправить», «открыть в Авито».

**Важно:** в уведомление уходит **обезличенный** текст и код клиента вида
`К-417`. Иначе мы аккуратно вычистили корпус, а потом сольём персональные
данные через служебный канал. Нужен оригинал — кнопка открывает чат в
приложении Авито.

Здесь ловятся последние промахи на живых людях, но без риска.

**Как это запускается.** Связка собрана в `src/draft_loop.py`:

```bash
python3 src/draft_loop.py --dry-run   # посмотреть, ничего не отправляя
python3 src/draft_loop.py             # рабочий режим
```

Она читает непрочитанные чаты, готовит ответ движком и шлёт специалисту в
Telegram: код клиента, обезличенный текст вопроса, черновик и кнопки
«отправить / поправить / пропустить / открыть в Авито». Клиенту не уходит
ничего, пока кнопку не нажали. Текст, который специалист напишет сам,
проходит тот же фильтр: правила площадки одни для всех.

Это **эталон, а не коробка**. Telegram здесь потому, что он уже есть на
экзамене; у вас может быть веб-панель или почта — тогда меняется способ
показа, а остальное остаётся. Проверьте на своём аккаунте, прежде чем
пускать на клиентов: у Авито бывают особенности по типам чатов и правам
тарифа.

## Этап 3. Автономия

Бот отвечает сам на темы, где не ошибся ни разу. Остальное — по-прежнему
через подтверждение. Список тем расширяется постепенно.

`guard.py` работает на всех трёх этапах без исключений.

## Перед выходом на площадку

- [ ] `TZ.md` заполнен и согласован со специалистом
- [ ] Отключить встроенный ассистент площадки, иначе клиент получит два ответа
- [ ] Заполнен `knowledge/usloviya.md`, дата свежая
- [ ] Аудит корпуса: ноль находок
- [ ] Сервер в РФ, база данных и бэкапы обсуждены
- [ ] Проверка безопасности по `SECURITY.md`: по коду, затем ещё раз после выкладки
- [ ] Поручение на обработку персональных данных подписано
