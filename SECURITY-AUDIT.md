# Проверка безопасности шаблона — что и как проверялось

Короткая публичная выжимка. Полные рабочие отчёты остались у авторов: в них
детали чужой инфраструктуры, которым в шаблоне не место.

## Что проверяли

Пять проходов перед публикацией, последний — 21.09.2026.

1. **Секреты и личные данные** — все файлы, вся история git, сообщения коммитов,
   имена и почты авторов, неотслеживаемые файлы. Правила: телефоны во всех
   написаниях, почты, паспорта, СНИЛС, карты, ключи API и токены популярных
   провайдеров, приватные ключи, строки подключения к базам, плюс список
   личных терминов владельца — кириллицей и латиницей.
2. **Методика прежнего владельца** — то, что не ловится сканером: список
   вопросов клиенту, формулы расчёта, фирменные фразы и смайлики, названия
   партнёров, порядок программ в шаблоне условий, род глаголов. Всё нишевое
   вынесено в `config/niche.py` и `knowledge/usloviya.md`, которые каждый
   заполняет под себя.
3. **Инфраструктура авторов** — хостинги, адреса, порты туннелей, имена
   контейнеров и служб шлюза. Из документации и скриптов убрано; всё, что
   зависит от вашего шлюза, берётся из окружения.
4. **Код** — независимый review четырьмя языковыми моделями «как в первый
   раз», затем повторный проход после правок. Закрыто около шестидесяти
   находок: от неработающего движка (потерянная функция при переносе) до
   ложных срабатываний фильтра на обычных фразах клиента.
5. **Глазами постороннего** — свежий клон по https без ключей, путь по
   README → START-HERE → SETUP, запуск всех команд из документации.

## Что защищает того, кто возьмёт шаблон

- Обезличивание — единственная дверь наружу, с проверкой на выходе и тестами
  на каждую форму данных.
- Фильтр исходящих: контакты, увод с площадки, обещания результата, раскрытие
  помощника, остатки обезличивания, цена не вовремя.
- Сообщение клиента в контексте модели — данные с явными границами, не
  инструкции; поддельные границы вырезаются.
- Шлюз: без `https` — только локальный адрес; без редиректов и прокси; любая
  ерунда от шлюза — штатный отказ без внутренностей.
- Тренировочный бот: только личные чаты, пароль обязателен, смена пароля
  отзывает доступ, база 0600, правки обезличиваются.
- Файлы: символические ссылки не индексируются, секреты создаются сразу с 0600.
- Проверки перед коммитом и публикацией — pre-commit и pre-push хуки, CI без
  секретов и с правами только на чтение.
- 65 тестов: обезличивание (включая все найденные обходы), фильтр, движок с
  подставным шлюзом, связка черновиков, инъекции через историю, сами проверки.

## Сторонний аудит после публикации — 21.09.2026

Опубликованный шаблон отдали на проверку модели другого производителя, «как в
первый раз». Что она нашла и что с этим сделано:

| Находка | Что сделано |
|---|---|
| Обезличивание пропускало латинские имена («My name is John Smith»), координаты, адрес без слова «улица» («живу на Невского 15») и короткие фамилии («Я Ким»), а проверка на выходе этого не видела | Добавлены правила и те же классы в проверку на выходе; тесты на каждую форму |
| Проверка на выходе работала «открыто»: нашла остаток после повторной чистки — всё равно отправляла | Закрыта: остаток → запрос не уходит, разговор специалисту, запись в журнал |
| При прямом подключении к провайдеру системный промпт не подавался вовсе | Движок читает `prompt/SOUL.md` и отправляет отдельным сообщением; нет файла — предупреждение |
| Файл условий без строки «Годен до» разрешал цифры бессрочно | Нет срока — цифры заморожены, как при истёкшем |
| Тренировочный бот хранил `chat_id` без возможности удалить, пароль оставался в переписке | Команда `/забыть`, сообщение с паролем удаляется после входа |
| Клиент Telegram шёл через прокси из окружения и позволял редиректы | Тот же закалённый opener, что у шлюза и Авито |
| Действие в CI закреплено тегом, а не SHA | Закреплено по SHA, обновления через dependabot |
| Документация обещала «уходит только обезличенный текст» без оговорок | Границы описаны честно: что закрывают правила и что происходит, когда они не справились |
| Не указана версия Python и ОС | `pyproject.toml`, требования в README |
| Нет проверки готовности одной командой и демо без ключей | `scripts/check-env.py` расширен до проверки файлов и прав; `scripts/demo.py` |

### Третий и четвёртый заходы — 21–22.09.2026

Опубликованную версию отдали ещё двум проверяющим: один ломал обезличивание и
фильтр, второй прошёл путь новичка по документации с нуля. Оба работали на
свежем клоне, без доступа к истории проекта.

**Что нашёл первый.** Обезличивание закрывало только канонические написания:
телефон числительными («восемь девятьсот двенадцать…»), с латинскими `O`
вместо нулей, со звёздочками и запятыми между группами, с невидимыми знаками;
латинские имена; короткие и редкие фамилии («клиент Ли», «это Черных»);
координаты без пробела после запятой; «серия 4510 номер 123456»; почта и ник,
записанные словами. 76 форм из 125 уходили к модели нетронутыми, и проверка на
выходе их не видела, потому что была тем же набором правил. Фильтр исходящих
пропускал 66 фраз из 81: просьбу оставить номер, обещание позвонить, «в о т с
а п» через пробел, «Обещаю, вам одобрят», «Я программа», «с вами свяжется наш
менеджер», цену словами и долей от суммы.

Чинилось не добавлением правил — так можно бесконечно. Развели две задачи:
маскировка чистит что умеет, а проверка на выходе намеренно шире её и не имеет
права пропустить. Непокрытая форма теперь не уходит наружу, а передаётся
специалисту. Плюс нормализация входа: невидимые знаки, буквы вместо цифр,
числительные, разрядка. Проверено: ноль пропусков на 20 формах обезличивания и
45 фразах фильтра, ноль ложных срабатываний на 26 обычных репликах.

Тот же заход нашёл три вещи помимо правил: поддельные границы блока клиента
вырезались только из текущего сообщения (через историю, карточку клиента и
куски базы знаний инъекция проходила); чекпоинт выгрузки хранил сырые
идентификаторы чатов рядом с последовательной нумерацией диалогов — то есть
был той самой таблицей соответствий, которых в проекте быть не должно; связка
этапа 2 отдавала движку историю в чужом формате и падала на любом чате с
предыдущими репликами.

**Что нашёл второй.** Путь новичка — 3/10 для непрограммиста. Обязательный шаг
«аудит корпуса» не имел команды, и проверить корпус было нечем: остальные
проверки смотрят файлы под git, а `corpus/` в `.gitignore`. Этап 2 нельзя было
запустить: документация обещала, что id чата виден в выводе бота, а бот его не
печатал. Специалисту с распространённым именем шаблон блокировал каждый коммит
из-за собственных примеров. Инструкция сама себе противоречила: одна команда
создавала настройки, следующая их стирала.

Всё перечисленное закрыто, инструкция переписана в два блока — до работающего
тренировочного бота и после.

**Что осталось открытым**, и это стоит знать тому, кто берёт шаблон:

- Двоичные файлы (PDF, изображения, архивы) проверка личных данных не читает —
  только ищет в них ключи и смотрит на имя. Поэтому в репозиторий их класть
  нельзя; проверка теперь останавливает коммит с таким файлом.
- Защита от инструкций внутри кусков базы знаний — текстовая (границы и
  пометка «не инструкции»), отдельного детектора нет. Фильтр на выходе
  ограничивает ущерб, но не доказывает, что промпт нельзя вытащить.
- Туннель, шлюз, бэкапы и восстановление — вне репозитория; шаблон их не
  проверяет (см. `docs/arhitektura.md`).
- Sca-инструменты (gitleaks, trufflehog) в CI не стоят: зависимостей у проекта
  нет, а секреты ищет своя проверка по истории. Поставить gitleaks сверху —
  разумно, если репозиторий живёт долго.

## Что оставлено намеренно

- README честно говорит, что шаблон собран под ипотечного брокера.
- Примеры в `.env.example`, комментариях и `config/examples/` помечены как примеры.
- В словарях обезличивания есть города и имена — это словари, а не чьи-то данные.
- `config/niche.py` — исполняемый Python: удобно, но в чужом форке его нужно
  прочитать глазами до запуска (см. `SECURITY.md`).
